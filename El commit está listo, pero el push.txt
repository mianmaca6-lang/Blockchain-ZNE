## Paso a paso para desplegar

El detalle completo, con todos los comandos, está en [docs/DESPLIEGUE.md](Blockchain-ZNE-main/docs/DESPLIEGUE.md), que también va en el commit. En resumen:

1. **Subir el código:** haz el push de arriba y fusiona el pull request.
2. **Respaldar la base de datos del servidor antes de desplegar (D4):** desde el contenedor que corre hoy, copia `data/colmena.db` a `backups/` con la API de backup de SQLite, y guarda una copia fuera del proyecto.
3. **Preparar los secretos en el servidor:** crea `.env` a partir de `.env.example` y genera `COLMENA_API_TOKEN`, `COLMENA_CLAVE_CIFRADO` y `COLMENA_SECRETO_SEUDONIMO`. **Guarda la clave de cifrado fuera del servidor:** si se pierde, los registros personales no se pueden recuperar.
4. **Desplegar el backend:** `git pull` y luego `docker compose up -d --build`. El contenedor respalda la base, adopta la base antigua sin perder datos y migra a la revisión 0002. Si algo falla, la API no arranca y puedes restaurar el respaldo.
5. **Desplegar el contrato en Testnet**, en una máquina donde puedas instalar stellar-cli:
   - Crea las llaves `colmena-admin` y `colmena-servicio` con `stellar keys generate`.
   - Ejecuta `sh contratos/scripts/desplegar_testnet.sh`.
   - Copia el ID del contrato al `.env` del servidor.
   - Pon la llave de servicio como archivo en `secrets/` (nunca dentro del `.env`).
6. **Conectar n8n:** un nodo HTTP Request a `POST /api/v1/registros`.
   - El token va como credencial *Header Auth*.
   - Usa `Idempotency-Key: telegram-<chat_id>-<message_id>`.
   - El nodo de facturas también debe usar el token nuevo, porque el antiguo ya no funciona.
7. **Verificar:**

   - `alembic current` muestra `0002`.
